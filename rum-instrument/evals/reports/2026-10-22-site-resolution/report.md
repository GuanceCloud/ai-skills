# RUM 地址解析修复验证

日期：2026-10-22。执行宿主：macOS。范围：仓库源码，不修改本机已安装 Skill，不消费真实授权码。

## 修改与边界

- 普通 OpenWay 与 RUM OpenWay 按首个 DNS 标签的服务名称关联同一官方目录条目；目录不需要 RUM 地址字段，SDK 接收地址保持不变。
- 先使用关联当前部署的非敏感配置；否则查官方目录；有明确部署命名约定时才允许规则推导。`--site-config` 是 Agent 从实际证据准备的内部快照，不是用户新增必填项，也不是对任意文件的自动信任。
- 部署记录绑定接收地址、AI API 与来源，并进入凭据身份校验。旧官方目录计划及状态绑定保持兼容。
- DataWay 探测失败记录为 unverified，不阻塞凭据解析；AI API 连接/TLS 失败仍在读取授权码之前阻断。
- 保留 HTTP(S) origin、内嵌账号密码、路径和参数检查；部署 AI API 必须为 HTTPS，不扩展测试站 TLS 例外。
- 评审发现的默认端口绕过已修复：内置测试站识别与覆盖保护统一按协议、主机、有效端口比较，显式 `:80` 仍使用固定 AI API，SDK 接收地址保留用户的规范化输入。

新增测试以两个品牌、13 个站点键（含未来站点占位）的普通/RUM 两类地址回放目录，验证不依赖硬编码区域清单。覆盖实际 AI API 不遵循上报域名命名的目录条目、默认端口、伪造后缀、非默认端口不误匹配、冲突目录、独立部署域名/端口、命名约定最后回退、测试站覆盖拒绝、配置错配、旧 CLI、无凭据探测及恢复不重复换码。

评审修复先通过新增测试复现默认端口导致的站点识别和覆盖保护失败，再修复并执行完整回归。覆盖 `:80`、`:080`、大小写和尾斜杠；不同协议、伪造域名和非默认端口不会被识别为内置测试站。计划执行中的覆盖尝试在读取授权码和调用换码 API 前被拒绝。

验证期间解析文件曾被外部恢复，获得用户允许后恢复已保存实现，最终测试与交付文件哈希一致。一次隔离副本测试漏带 evals 夹具，产生文件缺失错误；最终在完整仓库复跑上述 257 项全部通过。
